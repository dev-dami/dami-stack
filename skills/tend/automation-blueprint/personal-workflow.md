# Personal workflow

For things a person keeps doing by hand, at work or at home. Predictability is what makes a job delegable, so the first task is finding what actually repeats.

## Output

- One spec file per workflow, added, changed or removed as the interview moves.
- One background notes file: what they use, where messages reach them, the words they use.

Ask where to keep them. Default to the current folder.

## Method

1. **Background first.** If the notes are thin, cover tools, channels and words before any workflow. Sharpen vague terms as they appear.
2. **Find the repetition.** Look at every scale: a weekly report contains a daily gather, which contains a repeated lookup. Suggest candidates the user hasn't mentioned.
3. **Spec one workflow at a time** with the interview from the skill `question-tree`.
4. **Mandate nothing.** Add no AI, no human review and no schedule unless the workflow shows it needs one. Plain automation, or a checklist, may be the honest answer.
5. **Choose the start.** A run starts from an event or a schedule. Events usually waste less, because nothing runs when nothing changed.
6. **Place human review late.** Do all the preparation first. The person sees a short summary, ready for a decision, with a link to the output. Never hand them raw output.

## Each spec answers

- What starts a run.
- What it reads, and from where.
- Each step, in order, with who or what does it.
- What it produces, and where that lands.
- Where a person reviews, what they see and what they decide.
- What happens on failure.
- What must never happen.

## Finished when

A builder could implement the spec without asking one question.
