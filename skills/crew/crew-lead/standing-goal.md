# Standing goal

For a goal that runs across a very long session. You are the single accountable owner, with two aims held together: deliver today's item, and leave conditions better for whatever follows.

Agree the goal with the user before starting.

## How to run it

1. **Delegate.** All work goes to workers, in the background. That protects your context and keeps you available to the user. At solo level there are no workers: take one bounded item at a time and update the pages before your context fills.
2. **Look for gains before each task.** Ask what would make this kind of task easier or safer for good: a narrowly constrained function, a lint rule that forces correctness, a standard that can be enforced, access to logs, test data or a browser.
3. **Keep the standard.** Allow no one-off workarounds. Fix convention breaches before feature work.
4. **Pick the size.** Use the skill `work-chart` and the steps in the skill `crew-lead` for large chunks.
5. **Review the environment.** Use the skill `after-action` on about one in five worker sessions, favouring failures. You decide which proposals to pursue.
6. **Suggest schedules** where the host allows them. Starting one is a G6 step.

Every outward step (publishing, pushing, merging, schedules) needs its OK, and so does any change to your own instructions.

## Memory

Keep memory as linked Markdown pages that outlast the session. Knowledge has to survive compaction, so it can't live only in your context.

**Where.** Prefer an existing shared set and adopt its conventions. Otherwise agree a location with the user before writing.

**Shape.**

- An index holds a one-line summary per page.
- Each page covers one topic.
- Pages cite sources and never copy them.

**Pages are history.**

- Each claim carries a date.
- A code claim names its repo and commit. Nothing about code is stated in the present tense without them.
- A later change appends a dated entry and marks the earlier claim as replaced.

**Use.** Consult the pages before deciding. File answers worth keeping. When a durable fact arrives, update every page it affects.

**Audit** periodically for contradictions, orphan pages and claims that later work has overtaken.

The stores stay separate. Pinned notes hold traps at a code location, the glossary holds words, and these pages hold the goal's knowledge.

## Done when

- The goal was agreed before work started.
- At the end of each item, its result is delivered or named as open, and the pages reflect what changed.
- The audit has run and its findings are fixed or listed.
- Every outward step ran under an OK.
- About a fifth of worker sessions went through the skill `after-action`, and the choice of what to pursue is recorded.
